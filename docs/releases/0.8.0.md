# SuperZip 0.8.0

## Highlights

- Added a version-eight native `.suzip` GPU Huffman block. The encoder measures
  complete candidate sizes and uses the smaller block; CPU and AMD HIP readers
  verify and decode the new representation. Fully sampled blocks now omit
  absent symbols while retaining a complete decoder lookup. A RAM-only 1 MiB
  four-symbol regression fixture fell from 304,692 to 271,364 encoded payload
  bytes between efforts 5 and 6, with byte-exact CPU and HIP decode.
- Expanded GPU-native effort behavior with progressive entropy samples and
  bounded dictionary search. The previously identical GPU sizes on the 10 GiB
  Mixed benchmark are now distinct at all nine levels. The reviewed five-level
  [RAM-only report](https://github.com/strmt7/SuperZip/blob/0.8.0/docs/benchmarks/native-effort-2026-09-29.md) includes exact
  archive sizes, timings, and source/binary provenance.
- Added bounded native CPU Zstandard blocks and GPU long-sparse blocks while
  preserving read compatibility with older `.suzip` versions.
- Hardened archive read-back verification, extraction path and Unicode checks,
  malformed GPU block rejection, and codec error propagation.
- Published reproducible [cross-product benchmark methodology](https://github.com/strmt7/SuperZip/blob/0.8.0/docs/comparative-benchmark-methodology.md),
  reviewed comparison records, and generated graphs. Updated CLI diagnostics,
  repository skills, and verification workflows.
- Replaced the Silesia benchmark runner's MD5-only corpus gate with pinned
  SHA-256 validation while keeping historical measurement records intact.

## Compatibility And Limits

- This beta is a Windows 11 x64, AMD HIP-enabled release. GPU execution requires
  a supported AMD device and a compatible driver-provided HIP runtime.
- New version-eight `.suzip` Huffman blocks require a reader that supports
  version eight. This release continues to read older supported native versions.
- Compression effort is a search budget, not a promise that every input shrinks
  at every step. Incompressible or already optimal blocks may tie. The Mixed
  diagnostic had a 1,660-byte L6 size regression versus L5; no padding or
  deliberate degradation is used to manufacture size differences.
- Format-specific create/extract support and unsupported methods are listed in
  the [format matrix](https://github.com/strmt7/SuperZip/blob/0.8.0/docs/archive-format-support.md). Results from one benchmark
  corpus or GPU do not establish general speed or ratio superiority.
