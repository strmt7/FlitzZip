# FlitzZip 0.8.0

**Draft beta candidate.** Packages are published only after candidate validation
and maintainer approval. See [installation](../installing.md) for available
downloads and [release scope](../beta-readiness.md) for acceptance limits.

## Highlights

- FlitzZip provides a Windows archive manager, a command-line interface and the
  native `.flzip` format with AMD HIP acceleration. Compatibility formats use
  their documented CPU adapters.
- Experimental **Neutron star mode** is separate from efforts 1–9. It requires
  a compatible AMD HIP GPU and the required-GPU setting, and searches for the
  smallest complete candidate representation. Its extra computation can take
  substantially longer than numeric efforts.
- Native blocks add composition, byte-plane transforms and independent entropy
  contexts. New version-eleven blocks require a compatible reader; this release
  continues to read older supported native versions.
- GPU capability checks validate the driver, selected device, compiled targets
  and exact kernel payload before advertising support. CPU operations remain
  usable without an admitted GPU; required-HIP operations report the failure.

## Archive reliability

- Malformed trailing LHA headers and failed data skips now fail extraction
  instead of accepting an apparently complete prefix.
- Lzip and LZMA readers reject incomplete streams, invalid completion states and
  unsupported empty-member combinations. A single valid empty Lzip stream
  remains supported.
- Native readers reject trailing Deflate data, invalid indexes, overlapping
  payload windows and inconsistent block descriptors. Multi-window extraction
  reports progress and responds to cancellation before publishing the affected
  output.
- TAR extension sizes, global and local PAX overrides, GNU long names and
  USTAR directories follow their declared scope. CPIO readers reject missing
  trailer alignment. AR readers preserve ordinary symbol-like filenames and
  reject premature EOF. ISO readers reject unsupported attribute layouts and
  invalid volume bounds.
- CAB extraction preserves UTF-8 filenames and pins the input throughout
  validation and extraction. Invalid names and collisions fail before output.
- Output publication validates staged file ownership and anchors directory
  creation to open parent handles. Cancellation, allocation failure and malformed
  inputs retain cleanup and existing-output protections.
- Creating TAR or CPIO inside an input directory no longer includes the
  application's own staging files or omits legitimate temporary-looking files.

## Application improvements

- Batch extraction preserves both archives when their names would otherwise
  collide on Windows, including case differences and long names.
- File selection rejects oversized or incomplete shell results without silently
  truncating the Queue. Folder totals remain unavailable when the traversal
  cannot complete reliably.
- Keyboard focus stays on the same control as conditional actions appear.
  Queue checkboxes support repeated Space toggles, and list navigation remains
  available beside nonempty Queue and History lists.
- System graphs distinguish unavailable observations from measured zero and
  preserve missing-reading gaps. Drive selection uses one consistent inventory;
  CPU readings include systems with more than 64 logical processors.
- [User documentation](../README.md) now starts with installation, graphical
  workflows, CLI usage and troubleshooting. Developer procedures have a
  [separate entry point](../development/README.md).

## Performance evidence

The retained Pythia14M study reduced complete modeled archive size by 7.42%
against its same-setting Neutron baseline. Canterbury retained the preceding
1 MiB block sizes. The complete 991-file Govdocs1 study retained byte-exact
readback but showed only a small aggregate size reduction against the earlier
pruning study. These results apply to those workloads and settings.

Neutron is not uniformly smaller than other formats: the retained Canterbury
result is slightly smaller than its ZIP/gzip references and larger than bzip2
and XZ. Controlled comparative GPU timings remain unqualified. Consult the
[benchmark index](../benchmarks/README.md) for complete sizes, real HIP telemetry
and comparison limits.

## Requirements and known limitations

The runtime target is Windows 11 x64. GPU execution requires a supported AMD
device and compatible driver-provided HIP runtime. Compilation covers the
[release GPU targets](../release.md#gpu-targets); runtime evidence covers the
devices actually exercised. Unsupported archive methods fail explicitly; see
the [format matrix](../archive-format-support.md).

An earlier system freeze has no confirmed cause. A separate concurrent GPU
corruption report did not reproduce in subsequent focused tests and is accepted
as nonblocking by the maintainer. Neither result establishes a driver diagnosis;
a new mismatch reopens qualification. Details remain in
[release scope and limitations](../beta-readiness.md#outstanding-acceptance-limits).

Keep original files and verify restored contents before relying on prerelease
archives as the only copy of important data.

## For contributors

The build uses the pinned ROCm Core SDK 10.1.0, source-bound build receipts and
change-aware verification. Coverage acceptance requires effective tests for
critical and changed behavior, valid measurements and review of residual gaps;
universal 100% line coverage is not a release gate. See the
[developer guide](../development/README.md) and [release process](../release.md).

Candidate validation retains checksummed ZIP, MSI and corresponding-source
artifacts, including installer install/repair/uninstall checks. It creates no
release or tag. Publication requires separate approval and revalidates the exact
artifact hashes.
