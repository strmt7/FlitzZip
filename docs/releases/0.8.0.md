# SuperZip 0.8.0

**Draft intermediate beta candidate.** This version is configured in source,
but no beta tag or publication has been approved. The review packet separates
verified local results from blocked release gates.

## Highlights

- Added a version-eight native `.suzip` GPU Huffman block. The encoder measures
  complete candidate sizes and uses the smaller block; CPU and AMD HIP readers
  verify and decode the new representation. Fully sampled blocks now omit
  absent symbols while retaining a complete decoder lookup. A RAM-only 1 MiB
  four-symbol regression fixture fell from 304,692 to 271,364 encoded payload
  bytes between efforts 5 and 6, with byte-exact CPU and HIP decode.
- Expanded GPU-native effort behavior with progressive entropy samples and
  bounded dictionary search. GPU sizes on the 10 GiB Mixed diagnostic are
  distinct at all nine levels, though L6 is 1,660 bytes larger than L5. The
  [reviewed RAM-only report](https://github.com/strmt7/SuperZip/blob/0.8.0/docs/benchmarks/native-effort-2026-09-29.md)
  includes five paired timing levels and four single-run size diagnostics,
  with source/binary provenance. Full-sample Huffman coding reduced the Mixed
  L9 archive by 5,923,188 bytes relative to the prior source checkpoint; this
  is a 0.13% size gain on that workload, not a universal speedup.
- Added bounded native CPU Zstandard blocks and GPU long-sparse blocks while
  preserving read compatibility with older `.suzip` versions.
- Hardened archive read-back verification, extraction path and Unicode checks,
  malformed GPU block rejection, and codec error propagation.
- Published reproducible [cross-product benchmark methodology](https://github.com/strmt7/SuperZip/blob/0.8.0/docs/comparative-benchmark-methodology.md),
  reviewed comparison records, and generated graphs. Updated CLI diagnostics,
  repository skills, and verification workflows.
- Replaced the Silesia benchmark runner's MD5-only corpus gate with pinned
  SHA-256 validation while keeping historical measurement records intact.
- Migrated to the complete pinned ROCm Core SDK 10.0.0 distribution and compiled
  all six release HIP targets. SDK components remain unmodified; driver/runtime
  prerequisites and observed component versions are recorded separately.
- Reduced development overhead through changed-component verification,
  explicit native build receipts, mandatory local code navigation and bounded
  context reads. Scientific RAM studies now retain pilots and frozen
  confirmations, with up to 1,024 planned samples, complete wall-time admission,
  byte-exact validation and no speed-based exclusions.
- Recorded [all seven block sizes](../benchmarks/native-beta-blocks-2026-10-03.md),
  [all nine effort sizes](../benchmarks/native-beta-effort-sizes-2026-10-03.md) and
  [all 13 writable formats](../benchmarks/beta-format-sizes-2026-10-03.md). Only the
  8 MiB level-5 synthetic Mixed CPU/HIP timing case qualified descriptively.
  GPU archives were larger there; these records establish no universal ranking.
- Included the canonical logo, benchmark charts and design-reference assets in
  portable/MSI documentation so shipped relative image links resolve.

## Compatibility And Limits

- The candidate targets Windows 11 x64 with AMD HIP enabled. GPU execution requires
  a supported AMD device and a compatible driver-provided HIP runtime.
- New version-eight `.suzip` Huffman blocks require a reader that supports
  version eight. This release continues to read older supported native versions.
- Compression effort is a search budget, not a promise that every input shrinks
  at every step. Incompressible or already optimal blocks may tie. The Mixed
  diagnostic had a 1,660-byte L6 size regression versus L5; no padding or
  deliberate degradation is used to manufacture size differences.
- Format-specific create/extract support and unsupported methods are listed in
  the [format matrix](https://github.com/strmt7/SuperZip/blob/0.8.0/docs/archive-format-support.md). Results from one benchmark
  corpus or GPU do not establish general speed or ratio superiority.
- Unresolved code-scanning findings continue to block release acceptance.
  MSI install/repair/uninstall smoke requires an isolated elevated host; the
  existing local installation was preserved. Additional profile/corpus and
  comparator timing qualification remains incomplete. This is an internal
  review candidate, not an enterprise-readiness or publication approval claim.
