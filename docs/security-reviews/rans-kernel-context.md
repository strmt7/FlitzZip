# Private rANS Kernel Context Review

This review applies the maintainer's authorization for individually proven
false positives. The listed reported files, highlighted locations, rules and
scanner versions remain unchanged. Existing decisions renew their changed build
and module context; additional HIP-host parser reports are reviewed
individually below. No public archive representation is admitted.
Raw reports and the preceding individual evidence remain retained.

For these decisions, superseded review narratives are referenced through the
[immutable predecessor ledger](https://github.com/strmt7/FlitzZip/blob/2ee2e910d5cf6924e0f09f6f865b8a4c459fba8f/.github/scanner-false-positive-reviews.csv).
The current binding retains every executable source, caller, test, build and
scanner path, together with this current evidence. Historical narrative edits
cannot change the referenced predecessor's evidence or current source identity.

The kernel module now uses private ABI version 3, with its new export, exact
layout and complete device-entry inventory changed together. Existing component
binders and entrypoints remain present. The additional translation unit owns
the bounded rANS decoder and private statistics kernels. They declare no allocator,
LHA callback, TAR helper or GDI state. Existing compiler definitions, source
membership and test registration remain unchanged; independent test sources are
added. The new tests use admitted immutable models and independently specified
decoded bytes. Qualification of that new path remains separate from these
static source and caller decisions.

The canonical HIP object command now rejects undefined, empty or relative
output paths before command generation. Configure-only controls exercise that
actual function. Its existing arguments, dependency paths and compiler launcher
are preserved; the new object's assigned output is included in the module.

The miniz and LHA reviews bind the changed build function and configure
fixtures, alongside their existing source and caller closure. The isolated
rANS implementation, POD and device tests neither allocate through miniz nor
retain Lhasa contexts, so they are not added as callers of those two reports.
Their existing context paths and scanner coverage are retained in full.

## Host Operation And Shared View

The host reader borrows exact resident input/output windows and uses the
canonical view's model workspace. It owns one charged model/plan/status
allocation through synchronous batch completion and status admission, before
checked normal release. Checkpoints see completed work; exceptions propagate
after an attempted drain. The caller retains the output through the existing
device CRC consumer. Neither host decoding nor a CPU fallback is introduced.

The address-only alias guard is shared by the portable view and HIP host
admission. Its body is identical to the preceding view-local implementation;
byte-membership cases independently exercise empty, adjacent, nested and
unrelated regions. The view's new payload accessor borrows immutable bytes and
changes no allocation, callback ownership, wire layout or decoding arithmetic.
Shared singleton fixtures emit the mathematical fixed-state identity, without
using a product encoder. Fixed independent byte arrays remain comparison oracles.

The LHA and miniz sources and direct callers are unchanged. The new isolated
host reader and tests do not register their callbacks or replace their allocators.
The TAR helper retains its same direct registered call, and the GDI loop retains
its same induction, providers and readbacks. Their earlier context paths remain
bound; unrelated new translation units are not substituted for those callers.
All listed device kernel bodies, component bindings and existing entrypoints
also remain unchanged. The additional CRC test consumes a live decoded window
through the existing synchronous CRC function; it does not alter the table,
decoded-block bounds, prefix packing or sparse kernel attributes below.

The changed native selector now includes both device suites when the shared
view or fixture changes, and includes the independent byte-region suite for
that shared helper. Exact-name controls retain every CPU reader case and require
HIP admission for device consumers. CMake and unknown native inputs still select
the broad driver. This strengthens qualification routing; it changes no allocator,
callback, registration macro, kernel body, scanner configuration or individual
decision below. The originally retained selector failure remains a failed record.

## Private Statistics Context

The statistics extension changes the private export, layout and complete device
entry inventory together. It retains all preceding entries and binders. The new
translation unit accumulates bounded source tiles, records actual predecessors
at later segment starts, and projects exact integer counts. Shared-memory
barriers have block-uniform admission and participation; independent projection
lanes check subtraction and sums before writing. Its accumulating buffers and
source are separately owned by the caller and remain live through completion.
The new shader is also in the canonical device-coverage source inventory.

These changes do not alter any individually reported source, highlighted
location or its existing direct caller. The allocator branch, LHA destruction
order, TAR registration, GDI induction and existing device reads remain as
described below. New independent raw-count tests are qualification requirements,
not evidence of execution until they pass against current HIP binaries. Neither
histogram construction nor ABI extension opens archive admission or changes
numeric efforts. Every prior source, scanner and executable context path remains
retained; the new statistics source and controls are additional context for the
device reports, not replacements for their existing callers.

## Statistics Operation Context

The added host operation calls the existing statistics entries on the same
per-thread stream. It owns a separately charged scratch allocation, borrows
immutable source storage, resets statuses before reuse and inspects them only
after dispatch completion. Completed base counts and boundary corrections can
be reused; cancellation invalidates the correction and projection caches.
These ownership and cache contracts require their own real-device qualification.
They do not certify full model mass or open public archive admission.

The CMake change adds only this host translation unit. All reported device
functions, their definitions and reads, module binders, allocation definitions,
LHA callback owners, TAR registration and GDI test bodies remain byte-identical.
The count test source retains its preceding cases and adds independent operation
and cancellation controls. The selector adds those direct consumers and preserves
the broad CMake path. For each individual decision below, these context changes
alter neither its highlighted expression nor the reason for its classification.
All prior context paths, source locations, rules and producer identities remain
bound. This review does not admit other findings or runtime memory-safety claims.

### Alert 10240

CodeQL 2.27.4's HIP-host analysis reports `__device__` as an unread static
variable at the declaration of `valid_rans_plan`. It is the HIP function
qualifier, not an object declaration. The function returns the metadata-admission
predicate and is called by `decode_rans_segments` before segment decoding.
The typed entry remains bound in the checksum-admitted module and complete
device-entry inventory. Guarded device cases exercise accepted plans, unsupported
precision/context widths, excessive segment work and uncontained extents.
Removing this qualifier or admission function would damage the device boundary.
This decision binds only that exact reported qualifier, location and producer.

### Alert 10241

CodeQL 2.27.4's HIP-host analysis reports local `frequency` as an unread static
variable. It is a local constant, and the immediately following state update
multiplies by it. The selected CDF interval is positive and bounded by the
full-width model mass. Both the portable reader and HIP fixtures require that
same frequency-dependent rANS recurrence; independent binary and segmented
payloads, stream consumption and terminal-state controls exercise it. Removing
or replacing the read would change decoding. This decision binds only the exact
reported local declaration, source bytes, location and producer.

## Transition-Statistics Classification

The following decisions concern HIP language classification and direct
definition/use evidence, rather than certification of GPU memory safety.
Their binding includes the complete reported translation unit, its direct
independent GPU tests, pinned compiler launcher and SDK identity, scanner
configuration, authorization and this evidence. Existing reports retain all
their preceding executable context paths.

The complete CPU and HIP-host CodeQL analyses of
`67c98d9ace17b46c3a12802ce22df7edf3ca129c` succeeded. Each report below occurs only
in CodeQL 2.27.4's HIP-host category. Raw SARIF and every occurrence response
remain retained. Required-HIP tests independently compare raw transitions,
segment-start removals and projected counts, including dispatch tails and the
maximum admitted source; they do not use normalization to conceal wrong counts.

AMD's [language reference](https://rocm.docs.amd.com/projects/HIP/en/docs-10.1.0/how-to/hip_cpp_language_extensions.html#function-type-qualifiers)
defines the kernel qualifier. CodeQL's [support table](https://codeql.github.com/docs/codeql-overview/supported-languages-and-frameworks/)
describes its C/C++ language/compiler coverage; this repository does not claim
HIP device extraction from a successful host analysis. No new extractor option,
compiler shim, query filter or source rewrite is introduced by these decisions.

### Alert 10242

`tile_bytes` is a local constant, not a static object. The immediately following
loop reads it as the bound on each lane's local source index. The bound is the
smaller of the remaining source extent and one tile. Independent raw-count cases
exercise partial final tiles and dispatch boundaries, and preserve input guards.
Removing that bound or substituting an unrestricted tile would damage the
source extent contract. This decision binds only its exact declaration and read.

### Alert 10243

`begin` is a local constant, not a static object. The next expression subtracts
it from the complete source extent; the loop then adds it to each local index.
The admitted first-tile offset remains absolute across dispatches. Multi-dispatch
raw-count comparisons require the later ranges to visit their own bytes and
retain the actual preceding source byte. This decision binds that exact offset
declaration, complete source and producer, not another arithmetic report.

### Alert 10244

`bucket` is a local constant, not a static object. It selects predecessor groups
in the source loop and contributes the high bits of the global histogram index
when shared bins are published. The raw transition oracle compares every cell
and exact total mass across varied predecessors; a zero-work or constant-bucket
substitute cannot satisfy it. Both reads remain in the unchanged kernel body.

### Alert 10245

`__global__` qualifies `count_rans_transitions` as a HIP kernel and is not an
object declaration. Its typed entry is bound in the private module and launched
by the direct transition-count cases. Real device execution produces the exact
independent histogram and preserves guards; host compilation alone cannot
establish those results. Removing the qualifier would destroy this kernel's
launch contract. The decision applies only to this exact reported qualifier.
